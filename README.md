# pathrelay

[![Release](https://img.shields.io/github/v/release/forghani77/pathrelay)](https://github.com/forghani77/pathrelay/releases)
[![Tests](https://img.shields.io/badge/tests-go_test-brightgreen)]()

pathrelay is a small HTTP reverse proxy that forwards incoming requests to an
upstream base URL, dialing the upstream through a **SOCKS5** or **HTTP
CONNECT** proxy. Ships with a built-in installer that sets up a hardened
**systemd** service and shell completions.

```
client ──▶ pathrelay ──▶ SOCKS5 / HTTP CONNECT proxy ──▶ upstream target
```

## Features

- Forward all HTTP requests to `--target`, preserving method, headers and body
- Outbound connection via SOCKS5 (`--socks`) or HTTP CONNECT (`--http`) proxy
- Redirects are never followed (`http.ErrUseLastResponse`)
- `pathrelay install` — installs binary, shell completions (bash/zsh/fish) and
  a hardened systemd service built from the flags you pass
- `pathrelay uninstall` — removes everything again
- Dynamic shell completion built in (cobra)

## Install

### Install script (from GitHub releases)

Latest release, Linux/macOS amd64/arm64:

```sh
curl -fsSL https://raw.githubusercontent.com/forghani77/pathrelay/main/install.sh | sh
```

Or clone and run it locally:

```sh
git clone https://github.com/forghani77/pathrelay && cd pathrelay
./install.sh              # latest release
./install.sh v1.2.3       # specific release
PREFIX=$HOME/.local ./install.sh   # custom prefix
```

The script verifies the tarball against `checksums.txt` (SHA-256) before
installing to `$PREFIX/bin/pathrelay`.

It also installs **shell completion for every supported shell found on the
system** — bash, zsh and fish:

- **bash**: `/etc/bash_completion.d` when the bash-completion package is
  present; otherwise a guarded eval block in `~/.bashrc` (plus a
  `.bash_profile` source line for login shells; skipped on bash < 4.4)
- **zsh**: a writable system `site-functions` dir; otherwise a guarded eval
  block in `~/.zshrc` (works regardless of `fpath`/`compinit` setup)
- **fish**: `~/.config/fish/completions`

Force a single shell with `FORCE_SHELL=bash|zsh|fish`. When run under `sudo`,
rc files are edited for the invoking user, not root.

### From source

```sh
go install github.com/forghani77/pathrelay@latest
# or
git clone https://github.com/forghani77/pathrelay && cd pathrelay
go build -o pathrelay .
```

## Quick start

Run in the foreground:

```sh
pathrelay --listen :8080 --target https://mydomain:2096 --socks localhost:1080
```

Via an HTTP CONNECT proxy instead:

```sh
pathrelay --listen :8080 --target https://mydomain:2096 --http 127.0.0.1:3128
```

Every request path is appended to the target base URL:
`GET /foo/bar` → `https://mydomain:2096/foo/bar`.

### Flags

| Flag | Short | Default | Description |
|------|-------|---------|-------------|
| `--listen` | `-l` | `:80` | Address to listen on |
| `--target` | `-t` | `https://mydomain:2096` | Upstream target base URL |
| `--socks` | `-s` | `localhost:1080` | SOCKS5 proxy address (exclusive with `--http`) |
| `--http` | | | HTTP CONNECT proxy address (exclusive with `--socks`) |
| `--version` | `-v` | | Print version and exit |
| `--help` | `-h` | | Help for any command |

## systemd service

Install as a service configured with the flags you pass (requires root):

```sh
sudo pathrelay install --listen :8080 --target https://mydomain:2096 --socks localhost:1080
# or with an HTTP proxy:
sudo pathrelay install --listen :80 --target https://mydomain:2096 --http 10.0.0.2:3128
```

`install` performs, in order:

1. Copies the binary to `/usr/local/bin/pathrelay`
2. Writes shell completion scripts for installed shells
   (`/etc/bash_completion.d`, `/usr/local/share/zsh/site-functions`, `/etc/fish/completions`)
3. Writes `/etc/systemd/system/pathrelay.service`, runs `systemctl daemon-reload`
   and `systemctl enable --now pathrelay.service`

The unit runs under a `DynamicUser` with `ProtectSystem=strict`,
`NoNewPrivileges`, `PrivateTmp`, `PrivateDevices` and other hardening options
enabled, and restarts on failure.

Manage the service:

```sh
systemctl status pathrelay
journalctl -u pathrelay -f
```

To change the service configuration, re-run `install` with new flags — the
unit file is rewritten and the service restarted.

### Uninstall

```sh
sudo pathrelay uninstall
```

Stops and disables the service, removes the unit file, completion scripts and
the installed binary.

## Shell completion

Completions are generated by cobra. If you didn't use `install`:

```sh
pathrelay completion bash    # also: zsh, fish, powershell
```

## Releases

Releases are automated with GitHub Actions: pushing a tag `v*` runs the test
suite, cross-compiles `linux/amd64`, `linux/arm64`, `darwin/amd64` and
`darwin/arm64`, and publishes the tarballs plus a `checksums.txt` to a GitHub
release.

```sh
git tag v0.1.0 && git push origin v0.1.0
```

## Development

```sh
go test ./...        # run tests
go vet ./...         # static checks
go build -o pathrelay .   # build
```

Project layout:

```
main.go                  entry point
internal/cli/            cobra command tree (root, install, uninstall)
internal/app/            configuration + proxy server loop
internal/dialer/         SOCKS5 / HTTP CONNECT outbound dialers
internal/shellcomp/      shell completion install/remove
internal/sysd/           systemd unit generation, service install/uninstall
internal/version/        build-time version string
```
